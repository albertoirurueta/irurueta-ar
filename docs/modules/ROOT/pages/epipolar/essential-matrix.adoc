= Essential matrix
:stem: latexmath

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

The essential matrix stem:[\mathbf{E}] is the fundamental matrix's calibrated counterpart: the same epipolar constraint,
but written for image points that have been normalized by known camera intrinsics. If a scene is calibrated
(both cameras' intrinsic matrices stem:[\mathbf{K}], stem:[\mathbf{K}'] are known), stem:[\mathbf{E}] recovers not just the epipolar
geometry but an actual metric camera pair -- up to scale -- directly from two views. This is the bridge between
xref:epipolar/fundamental-matrix.adoc[] (purely projective) and a metric
xref:sfm/structure-from-motion.adoc[reconstruction].

== Relation to the fundamental matrix

For canonical cameras stem:[\mathbf{P} = \mathbf{K}[\mathbf{I}\,|\,\mathbf{0}\]] and stem:[\mathbf{P}' = \mathbf{K}'[\mathbf{R}\,|\,\mathbf{t}\]] (stem:[\mathbf{t} = -\mathbf{R}\mathbf{C}']), the fundamental
matrix expression from xref:epipolar/fundamental-matrix.adoc[] reduces to

[stem]
++++
\mathbf{F} = \mathbf{K}'^{-T}\, [\mathbf{t}]_\times \mathbf{R}\, \mathbf{K}^{-1}
++++

Normalizing points with the known intrinsics, stem:[\mathbf{\hat m} = \mathbf{K}^{-1} \mathbf{m}], stem:[\mathbf{\hat m}' = \mathbf{K}'^{-1} \mathbf{m}'], the
epipolar constraint stem:[\mathbf{\hat m}'^{T} \mathbf{E} \, \mathbf{\hat m} = 0] holds for

[stem]
++++
\mathbf{E} = \mathbf{K}'^{T} \mathbf{F} \mathbf{K} = [\mathbf{t}]_\times \mathbf{R}
++++

xref:reference.adoc#ref-thesis[Irurueta, PhD thesis] xref:attachment$irurueta-phd-thesis.pdf#page=138[&sect;3.2.7]. Unlike stem:[\mathbf{F}], stem:[\mathbf{E}] is not an arbitrary
rank-2 matrix: because it factors as a skew-symmetric matrix times a rotation, its SVD always has the form
stem:[\mathbf{E} = \mathbf{U}\,\mathrm{diag}(1,1,0)\,\mathbf{V}^{T}] -- two equal, non-zero singular values (defined up to the overall
scale of stem:[\mathbf{E}]) and a third that is exactly zero. Counting rotation (3 DOF) and translation direction (2 DOF
up to scale) confirms stem:[\mathbf{E}] has only **5 degrees of freedom**, two fewer than stem:[\mathbf{F}]'s 7.

Maps to `com.irurueta.ar.epipolar.EssentialMatrix`, with a constructor overload
`EssentialMatrix(FundamentalMatrix, PinholeCameraIntrinsicParameters leftIntrinsics,
PinholeCameraIntrinsicParameters rightIntrinsics)` that implements stem:[\mathbf{E} = \mathbf{K}'^{T}\mathbf{F}\mathbf{K}] directly, plus
overloads for building stem:[\mathbf{E}] straight from a `Rotation3D` + translation, or from a pair of `PinholeCamera`s.

== Recovering the camera pair: four-fold ambiguity

Because stem:[\mathbf{E} = [\mathbf{t}\]_\times \mathbf{R}] with stem:[\lVert \mathbf{t} \rVert = 1] (a convenient normalization of the baseline
length), its SVD-based decomposition stem:[\mathbf{E} = \mathbf{U}\,\mathrm{diag}(1,1,0)\,\mathbf{V}^{T}] admits, with

[stem]
++++
\mathbf{W} = \begin{bmatrix} 0 & -1 & 0 \\ 1 & 0 & 0 \\ 0 & 0 & 1 \end{bmatrix}
++++

two candidate rotations stem:[\mathbf{R} = \mathbf{U}\mathbf{W}\mathbf{V}^{T}] or stem:[\mathbf{U}\mathbf{W}^{T}\mathbf{V}^{T}], and translation stem:[\mathbf{t} = \pm \mathbf{u}_3] (the last
column of stem:[\mathbf{U}]) -- **four** combinations for the second camera stem:[\mathbf{P}' = \mathbf{K}'[\mathbf{R}\,|\,\mathbf{t}\]]. Two of the four are
a *twisted pair* related by a 180&deg; rotation about the baseline. Only one combination places every
triangulated 3D point in front of *both* cameras (correct cheirality); the other three put at least some points
behind a camera, so the standard disambiguation is to triangulate a handful of correspondences under all four
hypotheses and keep the one with the most positive cheiralities
xref:reference.adoc#ref-thesis[Irurueta, PhD thesis] xref:attachment$irurueta-phd-thesis.pdf#page=141[&sect;3.2.7.2].

Maps to `EssentialMatrix.computePossibleRotationAndTranslations()` +
`getFirstPossibleRotation()`/`getSecondPossibleRotation()` +
`getFirstPossibleTranslation()`/`getSecondPossibleTranslation()`. The cheirality-based disambiguation across
the four combinations is what `com.irurueta.ar.sfm.EssentialMatrixInitialCamerasEstimator` automates -- see
xref:sfm/structure-from-motion.adoc[].

== Example

[source,java]
----
// F already estimated (see epipolar/fundamental-matrix.adoc), K and K' known
var essential = new EssentialMatrix(fundamentalMatrix, leftIntrinsics, rightIntrinsics);
essential.computePossibleRotationAndTranslations();

Rotation3D rotationA = essential.getFirstPossibleRotation();
Rotation3D rotationB = essential.getSecondPossibleRotation();
Point2D translationA = essential.getFirstPossibleTranslation();
Point2D translationB = essential.getSecondPossibleTranslation();
// triangulate a few points under each of the 4 (rotation, translation) combinations
// and keep the one with all-positive cheirality (see sfm/structure-from-motion.adoc)
----
